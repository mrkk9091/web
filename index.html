Why AniOptimizer is Closed Source

Fork Protection
Prior open-source releases were stripped of attribution, rebranded, and redistributed with altered safety parameters that caused device instability and thermal damage. The closed binary guarantees that thermal limits, the protected process list, and safe mode behavior cannot be silently modified or removed in unauthorized forks. This protects users, not just the author.
🔒 Integrity Protection
Modified or tampered binaries distributed as "official" put users' devices at risk. Closed binaries guarantee that what you flash is exactly what was tested.
⚙️ Proprietary Algorithms
The stutter/jank split learning engine, EMA-based thermal predictor, and jank-class fusion logic took months to tune. Publishing the math defeats that entirely.
🚫 Misuse Prevention
Low-level sysfs and kernel interfaces in the wrong hands can brick devices. Keeping logic private prevents cargo-culted, broken ports that hurt users.
📦 Quality Control
A single maintained binary means one codebase to debug, profile, and harden. Forks dilute quality and create an ecosystem of half-working clones.
🤝 Trust & Accountability
As the sole distributor, accountability stays clear. If something breaks, there's one place to report it and one dev responsible for the fix.

Safety Evaluation Order (Every Poll Cycle)

  1. Thermal gate All zones read. Any zone above critical limit triggers immediate SAFE state. No dwell delay applies to safety drops. Safety is first-path, always.
  2. Safe mode gate Flag file checked. Persists across daemon restarts. Set by crash handler on abnormal exit. Device never re-enters an aggressive state blindly.
  3. Stability gate Live stability score evaluated. Aggressively decays on consecutive anomalies. Recovers slowly to prevent oscillation.
  4. Escalation allowed Only if all three gates pass, load signals are evaluated for potential state escalation. Escalation requires sustained load across the full 4-second dwell timer. Single-frame spikes are ignored.

Deliberately Excluded

  • EMA thermal prediction weights and forecast horizon constants
  • Stutter/jank classifier variance thresholds and feature vector
  • Per-SoC min/max frequency and power level tables
  • Game-specific learning model session data format
  • FSM transition weights between performance states

These constitute the tuning layer — the R&D investment. They affect how aggressively the daemon pursues performance within the safety envelope. They do not affect where the safety boundaries are drawn. Those boundaries are enforced by the initialization order and guard checks visible in the excerpts below.

🛡️ src/safety.c
Guards against thermal runaway, tracks a stability score, and enforces safe mode on crash or hard-temp breach.
CORE
This runs before any governor or GPU control is touched. Reads the persistent safe mode flag first — a crash on previous boot forces SAFE state unconditionally.
void safety_init(safety_ctx_t *ctx, int max_state) {
    memset(ctx, 0, sizeof(*ctx));
    ctx->stability_score    = 100;
    ctx->idle_baseline_temp = 50000;
    ctx->max_target_state   = max_state;
    if (sysfs_exists(SAFE_MODE_FILE)) {
        ctx->safe_mode_active   = true;
        ctx->safe_mode_start_ms = mono_ms();
    }
}

📚 src/learn.c
Per-game adaptive learning engine — builds a persistent profile per package, tracking session history and preferred states via EMA.
CORE
Package names are hashed via djb2 into deterministic filenames under the learn directory. Session state is tracked per-package without exposing app identity in logs.
static void pkg_to_filename(const char *pkg, char *out, size_t outsz) {
    uint32_t h = 5381;
    for (const char *p = pkg; *p; p++)
        h = ((h << 5) + h) + (unsigned char)*p;
    snprintf(out, outsz, LEARN_DIR "/%06x.dat", h & 0xFFFFFF);
}
void learn_session_start(game_learn_t *gl, const char *pkg) {
    str_copy(gl->pkg, pkg, sizeof(gl->pkg));
    gl->session_start_ms = mono_ms();
    gl->active           = true;
}
🎯 src/framepacing.c
Per-TID frame-pacing monitor using /proc schedstat — detects budget overruns without a single shell call.
CORE
Reads schedstat directly from /proc. No shell, no popen. Path construction is bounded and format-matched to kernel schedstat output.
static int read_schedstat(pid_t pid, pid_t tid,
                           uint64_t *run, uint64_t *wait, uint64_t *sw) {
    char path[128];
    snprintf(path, sizeof(path),
             "/proc/%d/task/%d/schedstat", (int)pid, (int)tid);
    char buf[64] = {0};
    if (sysfs_read(path, buf, sizeof(buf)) < 0) return -1;
    sscanf(buf, "%llu %llu %llu", run, wait, sw);
    return 0;
}
⚡ src/cpu.c
Sets governor, uclamp min/max, and affinity masks per-TID on all CPU clusters independently via sysfs.
SYS
Governor selection uses glob to discover all CPU clusters at runtime — no hardcoded paths, portable across heterogeneous SoC topologies.
void cpu_set_governor(const device_info_t *dev, const char *gov) {
    glob_t gl;
    glob("/sys/devices/system/cpu/cpu[0-9]*/cpufreq/scaling_governor",
         GLOB_NOSORT, NULL, &gl);
    for (size_t i = 0; i < gl.gl_pathc; i++)
        sysfs_write(gl.gl_pathv[i], gov);
    globfree(&gl);
}
🎮 src/gpu.c
Controls Adreno GPU power levels, min floor, and bus vote to guarantee a frequency floor during gameplay.
SYS
Sets both default_pwrlevel and min_pwrlevel in a single atomic pair — prevents the GPU from slipping below the intended floor between state transitions.
static void adreno_set_pwrlevel(const device_info_t *dev, int level) {
    char path[512];
    snprintf(path, sizeof(path), "%s/default_pwrlevel", dev->gpu_dev);
    sysfs_writef(path, "%d", level);
    snprintf(path, sizeof(path), "%s/min_pwrlevel", dev->gpu_dev);
    sysfs_writef(path, "%d", level);
}
